## Overview

The basic host/remote pattern is the entry point for Module Federation. Two independent applications run side by side: a **host** that consumes remote modules, and a **remote** that exposes them.

| App  | Role   | Port | Responsibility                        |
| ---- | ------ | ---- | ------------------------------------- |
| app1 | Host   | 3001 | Consumes `Button` from app2 at runtime |
| app2 | Remote | 3002 | Exposes `Button` via `remoteEntry.js` |

At runtime, the host fetches `http://localhost:3002/static/js/remoteEntry.js` — app2's container manifest — and resolves the `Button` module from there. No code from app2 is bundled into app1 at build time.

## Architecture

<Steps>
  <Step title="app2 builds and serves remoteEntry.js">
    When app2 starts, it generates `static/js/remoteEntry.js`. This file is app2's container — it registers the app's name, its exposed modules, and its shared dependencies.
  </Step>
  <Step title="app1 declares app2 as a remote">
    app1's webpack config maps the import prefix `app2` to app2's `remoteEntry.js` URL. No app2 code is bundled into app1.
  </Step>
  <Step title="app1 imports Button at runtime">
    When app1 renders, the browser fetches `remoteEntry.js` from app2, resolves the `Button` module, and renders it inside app1's component tree.
  </Step>
  <Step title="Shared React instance">
    Both apps declare `react` and `react-dom` as singletons. Only one copy of React is loaded, preventing hook errors from mismatched instances.
  </Step>
</Steps>

## Configuration

<CodeGroup>

```js app1/modern.config.js
import appTools, { defineConfig } from '@modern-js/app-tools';
import { ModuleFederationPlugin } from '@module-federation/enhanced/webpack';

export default defineConfig({
  server: {
    port: 3001,
  },
  runtime: {
    router: true,
  },
  source: {
    // Automatically generated asynchronous boundary via Dynamic Import,
    // allowing the page code to consume remote modules generated by
    // the module federation.
    enableAsyncEntry: true,
  },
  tools: {
    webpack: (config, { appendPlugins }) => {
      delete config.optimization.splitChunks;
      config.output.publicPath = 'auto';

      appendPlugins([
        new ModuleFederationPlugin({
          name: 'app1',
          remotes: {
            app2: 'app2@http://localhost:3002/static/js/remoteEntry.js',
          },
          shared: {
            react: { singleton: true },
            'react-dom': { singleton: true },
          },
        }),
      ]);
    },
  },
  plugins: [appTools()],
});
```

```js app2/modern.config.js
import appTools, { defineConfig } from '@modern-js/app-tools';
import { ModuleFederationPlugin } from '@module-federation/enhanced';

export default defineConfig({
  server: {
    port: 3002,
  },
  runtime: {
    router: true,
  },
  source: {
    // automatically generated asynchronous boundary via Dynamic Import,
    // allowing the page code to consume remote modules generated by
    // the module federation.
    enableAsyncEntry: true,
  },
  tools: {
    webpack: (config, { appendPlugins }) => {
      delete config.optimization.splitChunks;
      config.output.publicPath = 'auto';

      appendPlugins([
        new ModuleFederationPlugin({
          name: 'app2',
          library: { type: 'window', name: 'app2' },
          runtime: false,
          filename: 'static/js/remoteEntry.js',
          exposes: {
            './Button': './src/components/button.js',
          },
          shared: {
            react: { singleton: true },
            'react-dom': { singleton: true },
          },
        }),
      ]);
    },
  },
  plugins: [appTools()],
});
```

</CodeGroup>

### Key config fields

- **`name`** — a unique identifier for the federation container. Used as the global variable name when `library.type` is `window`.
- **`filename`** — the output path for the remote's container manifest (`remoteEntry.js`).
- **`exposes`** — maps public import paths to local source files. `'./Button'` becomes `app2/Button` in the host.
- **`remotes`** — maps an import prefix to a remote container. The format is `<name>@<url>`.
- **`shared`** — declares packages to share across containers. `singleton: true` ensures a single instance is used.

## The exposed component

app2 exposes a single `Button` component from `src/components/button.js`:

```js app2/src/components/button.js
import React from 'react';

const Button = () => (
  <button style={{ padding: '10px', background: 'red' }}>App 2 Button!!!!</button>
);

export default Button;
```

## Consuming the remote in app1

app1 imports `Button` using a bare import that references the remote container name and the exposed path:

```jsx app1/src/routes/page.jsx
import { Helmet } from '@modern-js/runtime/head';
import './index.css';
import Button from 'app2/Button';

const Index = () => (
  <div className="container-box">
    <h1>Basic Host-Remote</h1>
    <h2>App 1</h2>
    <main>
      <p className="description">
        FEDERATED: <Button />
      </p>
    </main>
  </div>
);

export default Index;
```

The import `app2/Button` resolves via the `remotes` mapping in app1's config: the `app2` prefix points to `http://localhost:3002/static/js/remoteEntry.js`, and `/Button` matches the `./Button` key in app2's `exposes`.

<Note>
  `enableAsyncEntry: true` in `source` generates an async boundary around the page entry so that dynamically loaded remote modules can be resolved before first render.
</Note>

## Running the example

<Steps>
  <Step title="Navigate to the example directory">
    ```bash
    cd basic-host-remote
    ```
  </Step>
  <Step title="Install dependencies">
    ```bash
    pnpm install
    ```
  </Step>
  <Step title="Start both applications">
    The `start` script runs app1 and app2 concurrently using pnpm workspaces.

    ```bash
    pnpm start
    ```
  </Step>
  <Step title="Open the applications">
    | URL                   | What you see                                          |
    | --------------------- | ----------------------------------------------------- |
    | http://localhost:3001 | app1 (host) rendering the Button loaded from app2     |
    | http://localhost:3002 | app2 (remote) running as a standalone application     |
  </Step>
</Steps>

## Key concepts demonstrated

<CardGroup cols={2}>
  <Card title="remoteEntry.js" icon="file-code">
    The container manifest served by the remote. The host fetches this file to discover what modules are available and how to load them.
  </Card>
  <Card title="Singleton sharing" icon="share-nodes">
    Declaring `react` and `react-dom` as singletons ensures both applications share the same React instance, which is required for hooks to work correctly across containers.
  </Card>
  <Card title="Async entry boundary" icon="bolt">
    `enableAsyncEntry` wraps the app entry in a dynamic import, giving webpack a point to inject asynchronous module resolution without blocking the initial render.
  </Card>
  <Card title="Independent deployment" icon="server">
    app2 runs on its own port and can be updated and redeployed without rebuilding app1. The host discovers changes the next time it loads `remoteEntry.js`.
  </Card>
</CardGroup>
